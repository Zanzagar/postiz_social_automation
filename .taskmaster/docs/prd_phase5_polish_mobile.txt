# PRD: Phase 5 — Polish & Mobile

## Overview
Add dark mode, in-app notifications with email digest, PWA support for mobile access, and rebuild the remaining untouched pages (Login, Health) through the Magic MCP pipeline.

## Background
Phases 1-4 delivered content iteration, templates, auto-publish, web intelligence, analytics, media catalog, calendar planning, multi-user, audience segmentation, and Postiz admin integration. This phase focuses on polish and accessibility — making the dashboard pleasant to use, keeping staff informed via email, and enabling mobile access for farm staff away from PCs.

**Phase 3 architecture changes (must account for):**
- **Google Drive is the central media repository.** Media files are NOT stored locally — only thumbnail cache (~2MB) lives on disk. Full files stream via Drive proxy.
- **Frontend pages added in Phase 3:** MediaPage (/media), CalendarPlanDialog, DriveImportDialog, SuggestedMediaPanel. All need dark mode audit.
- **Health page already has Media Catalog health card** (GET /api/media-health) with sync status, cleanup button. Phase 5 health enhancements should build on this.
- **New nav items:** Media page with Image icon in sidebar.
- **Video streaming:** Drive proxy with range requests serves videos. PWA offline mode should handle gracefully (show poster thumbnail when offline, not attempt to stream).

## Prerequisites
- Phases 1-4 complete: full feature set operational
- SMTP server available for email digest (Gmail, SendGrid, or temple email server)
- Users table populated with email addresses (added in this phase to notification_prefs)

## Features

### 1. Dark Mode
Theme toggle with system preference detection.

**Requirements:**
- CSS variables for all colors throughout the application (many already defined from shadcn/ui theme)
- Audit all components for hardcoded colors and replace with CSS variables
- Theme toggle: sun/moon icon in sidebar header area
- Store preference in localStorage (key: "gvsa-theme", values: "light"/"dark"/"system")
- Default: "system" — respect `prefers-color-scheme` media query
- Toggle cycles: system → light → dark → system
- All components rebuilt in earlier phases via Magic MCP should already use CSS variables — verify and fix any that don't
- No new API endpoints — purely frontend

### 2. In-App Toast Notifications
Real-time feedback for user actions and background events.

**Requirements:**
- Use shadcn/ui Toast component (already in project dependencies)
- Notification triggers:
  - Caption generation complete (success or error)
  - Post published by Postiz (success or error)
  - Content approved (when approval workflow is enabled)
  - Crawl/import complete (knowledge base, social history)
  - Auto-publish countdown started or completed
- Implementation: TanStack Query polling on key endpoints (health, drafts count, etc.) at configurable intervals (default: 30 seconds). When state changes detected, show toast.
- Notification bell icon in AppShell header: badge shows count of unread notifications since last check
- Click bell: dropdown showing recent notifications (last 20) with timestamps
- No WebSocket infrastructure — polling only
- Notifications stored in memory only (not persisted to database)

### 3. Email Digest
Configurable email summary of dashboard activity.

**Requirements:**
- `notification_prefs` table: id, user_id, email, digest_frequency (daily/weekly/off, default "off"), enabled_types (JSON array of event types), updated_at
- `email_digest_log` table: id, user_id, sent_at, content_hash, post_count, draft_count, error_count
- `GET /api/settings/notifications` endpoint: return current user's notification preferences
- `PUT /api/settings/notifications` endpoint: update preferences (email, frequency, enabled types)
- `POST /api/notifications/test-email` endpoint: send a test digest to verify SMTP config
- Digest content: posts published since last digest, drafts awaiting review, engagement highlights (top post, total reach), errors/failures, upcoming scheduled posts
- Email format: HTML email with simple, clean layout. Plain text fallback.
- Sending: Python smtplib with SMTP config from env vars (SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, SMTP_FROM)
- Scheduler: digest job runs daily at 8am local time (configurable). Weekly digest runs Monday at 8am.
- content_hash in digest_log prevents sending duplicate digests if job runs twice
- Settings page section: notification preferences (email, frequency, event types)

### 4. PWA — Progressive Web App
Enable "Add to Home Screen" and offline capabilities.

**Requirements:**
- Install vite-plugin-pwa as dev dependency
- `manifest.json`: name "Gita Valley Social", short_name "GV Social", theme_color matching brand (warm earth tone), background_color, icons (192x192 and 512x512 — create from Gita Valley logo or generate placeholder), display "standalone", start_url "/"
- Service worker: cache app shell (HTML, CSS, JS bundles) for offline access
- Offline behavior: when offline, show cached pages with "Offline — changes will sync when connected" banner
- **NOTE:** Media thumbnails are cached locally (media/thumbnails/) and served via FastAPI static mount + nginx proxy. Service worker should cache thumbnail requests. Full-res media streams from Drive proxy — show poster/thumbnail when offline, not attempt to stream.
- Offline draft editing: save draft content to IndexedDB when offline, sync to API when connection returns
- "Add to Home Screen" prompt: show install banner on first mobile visit (standard PWA behavior)
- No push notifications (using email digest instead)
- Test on mobile browsers: Chrome Android, Safari iOS

Extend existing Health page with checks for Phase 2-4 services.

**Requirements:**
